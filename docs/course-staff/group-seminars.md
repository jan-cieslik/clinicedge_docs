# Run a group seminar

**Access:** assigned classroom supervisor or application administrator. Open the classroom's **Group seminar** workspace.

## Open the run

1. Choose the published revision and seminar occurrence.
2. Select the **Live** tab; the workspace also has clinical and record/history views.
3. Review the vignette and optional soft time limit.
4. Choose **Open seminar**.
5. Ask students to start the occurrence and join.

Before a run opens, students see a waiting screen. Joining creates a sequence attempt, not an individual patient. Students still need classroom access and completed preceding activities.

Only one run can be open for the same published revision/occurrence.

## Release information

The vignette is initially available and cannot be hidden. Show/hide custom teaching items as the discussion develops. Request clinical findings from the imported case where configured; generated results are shared immediately and stored consistently for all joined learners.

Laboratory orders accumulate per source in a results table. Additional orders append new tests rather than rerolling existing measurements.

Students browse released items independently. Selecting a projected item does not force every student's view to follow it. Hiding the projected item returns the display to the vignette.

## Document the discussion

Use clinical documentation and the selected event types for the run. Publish only the explicit safe clinical summary intended for learners. Staff identities, private notes, judgments, and event details are not automatically projected.

The timer is a **soft** teaching aid. Editing the limit does not reset the original start time or turn expiry into automatic conclusion.

## Conclude and review

Confirm **Conclude seminar** when teaching is finished. Conclusion completes joined learners' sequence attempts and unlocks their next activity. Retained released content can be revisited subject to access rules.

In **Records > Seminars I supervised**, review runs you opened, concluded, or acted in. Open **Attendance** for a concluded run. **Add student to attendance** supports a genuinely missed participant using their username or sign-in ID, not secret PIN. The server checks access, revision and preceding progress; it rejects inconsistent additions rather than silently unlocking a different course.

Exports and individual records are private institutional data. Do not place them on a public display or in the documentation repository.
